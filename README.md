## Минимальные системные требования
| Пункт | Требование |
| --- | --- |
| ОС | Ubuntu Server 26.04 |
| ОЗУ | 1ГБ |
| Место на жёстком диске | 150ГБ |
| ЦП | Intel Pentium |

## Установка небходимых модулей
Для работы необходим podman-compose\
`sudo apt install podman-compose`
## Установка веб-приложения
Просто клонируйте репозиторий\
`git clone https://github.com/ZogirderCMD/antispam_detector_restapi`
## Настройка веб-приложения
В env файле установите параметры
| Название | За что отвечает |
| --- | --- |
| POSTGRES_DB | Имя базы данных |
| POSTGRES_USER | Имя пользователя базы данных |
| POSTGRES_PASSWORD | Пароль базы данных |
| POSTGRES_PORT | Порт базы данных |
| ADMIN_TOKEN | Токен администратора для просмотра логов |
| TZ | Зона времени |

Переименуйте env в .env\
`mv -i env .env`
## Запуск веб-приложения
Перейдите в папку с docker-compose.yaml и выполните команду podman-compose\
`podman-compose up --build -d`
## Документация API
### /analyze - POST
Анализ сообщения и его классификация, принимает сообщение методом form-data через параметр text\
Момжно использовать другую модель( RUSpam/spamNS_v1 или corall88/russian_spam_detector) через параметр model\
Возвращает JSON вида
```json
{
  "result": "POSITIVE",
  "score": "0.95"
}
```
Если вводимый текст пустой, то код ошибки 403
```json
{
  "result": "Text area is empty!"
}
```
### /history - GET
Показывает 20 последних запросов\
Возвращает JSON вида
```json
{
  "result": [
    {"id": 1,"model_name": "RUSpam/spamNS_v1","created_at": "дата"},
    {"id": 2,"model_name": "RUSpam/spamNS_v1","created_at": "дата"}
  ]
}
```
### /history/log_id - GET
Получить лог с соответствующим log_id\
Вместо log_id - число, т. е. идентификатор запроса\
Возвращает JSON вида
```json
{
  "input_text": "текст сообщения",
  "result": "POSITIVE",
  "score": "0.95"
}
```
Если пустой log_id, то код ошибки 403
```json
{
  "result": "Request ID is empty!"
}
```
Если запрос с таким log_id не найден, то код ошибки 403
```json
{
  "result": "Unknown request ID!"
}
```
### /health - GET
Проверить состояние сервиса\
Возвращает статус 200 - OK
### /admin_token/all_logs - GET
Просмотр всех логов сервера\
Вместо admin_token - токен доступа администратора\
Если будет неправильный токен, вернёт 404\
При успешном запросе
```json
{
  "result": [
    "дата1",
    "дата2",
    "дата3",
    "дата4"
  ]
}
```
### /admin_token/get_log/date - GET
Просмотр логов сервера по дате\
Вместо admin_token - токен доступа администратора\
Вместо date - дата лога\
Если будет неправильный токен, вернёт 404\
При успешном запросе
```json
{
  "result": {
    "время1": "лог1",
    "время2": "лог2",
    "время3": "лог3",
    "время4": "лог4"
  }
}
```
Если дата логов не существует, вернёт код 404
```json
{
  "result": "Log file with this date wasn't found!"
}
```
